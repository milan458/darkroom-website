How encrypted photo vaults work, in plain English

By Inertia Projects·Published 22 October 2026·Last updated 28 November 2026

Short answer

An encrypted photo vault app scrambles each photo with a secret key, so the stored file is unreadable without it. Your PIN, password or pattern is turned into that key, or into a key that unlocks it, on your phone and slowly on purpose, so guessing is expensive. A vault that only shows a PIN screen in front of ordinary files is hiding photos, not encrypting them.

A photo vault app works by encrypting each photo with a secret key, so the file stored on your phone or in the cloud is unreadable without that key. Your code (a PIN, password or pattern) is what unlocks the key, so the code is what an attacker has to guess. This guide is for anyone who searched "how does a vault app work" or "best iPhone encryption app" and wants to read a vault's security claims and know what they mean, without the math.

Vault apps love the word "encrypted". On its own it tells you very little. The sections below explain what real encryption involves, what a few popular apps say about theirs, and what no encryption can protect.

What's the difference between hiding and encrypting a photo?

Hiding puts a door in front of a normal photo. Encrypting turns the photo itself into unreadable data.

A vault that only hides stores your photos as ordinary image files inside the app, and shows a PIN screen before it displays them. Anyone who gets at those files another way (a computer backup, a forensic tool, a bug) sees the photos. An encrypting vault stores only scrambled data. Without the key, even a perfect copy of the files is useless. The iPhone's own Hidden album is the first kind: is the iPhone Hidden album private? explains why.

How does a PIN or pattern become an encryption key?

Through a key derivation function: a recipe that turns your code into a key. Good ones are deliberately slow, and the best are also memory-hungry, so each guess costs real time and hardware.

A key is a long random number. AES, the cipher NIST standardised in FIPS 197, uses keys of 128, 192 or 256 bits (NIST: AES). A 256-bit key has 2256 possible values, about 1077, so nobody guesses the key itself. Attackers go after the code that unlocks it instead.

That's why stretching matters. A 4-digit PIN has 10,000 possibilities. If each guess took a microsecond, a computer would try them all in a hundredth of a second. If each guess takes half a second, the same search takes about 83 minutes, and every extra character or bolt multiplies it.

  • Argon2id is a "memory-hard" function: each guess needs a set amount of memory as well as time, which raises the cost of dedicated cracking hardware. Its standard, RFC 9106, makes Argon2id the variant every implementation must support, and gives 64 MiB of memory with 3 passes as its second recommended setting for devices with less memory (RFC 9106).
  • PBKDF2-style functions repeat a hash many times. They're slow, but need little memory. NIST's guidance on password-based key derivation is SP 800-132, which NIST said in 2023 it plans to revise (NIST SP 800-132).
  • A plain hash, or nothing, means guesses are nearly free.

A random "salt" is mixed in too, so the same code never produces the same key in two vaults. RFC 9106 says a 128-bit salt is enough for all applications. Noxium, which we make, derives its keys from your pattern through Argon2id, and the pattern is never stored. Our pattern lock page shows how many patterns the 5×5 plate allows.

What do AES-256-GCM and "keys inside keys" mean?

AES-256-GCM is the cipher that scrambles the photos, in a mode that also detects tampering.

  • AES is the standard cipher (NIST FIPS 197).
  • 256 is the key size in bits.
  • GCM is a mode NIST calls "authenticated encryption" (NIST SP 800-38D). If the encrypted file is changed or damaged, decryption fails instead of producing a corrupted photo.

Marketing words like "military" or "bank" grade usually just mean AES. The questions that matter are what the key comes from, where it's kept, and whether the backup is encrypted too.

Good vaults also use keys inside keys, the same idea Apple uses for the iPhone's storage. In iOS Data Protection, every file has its own key, which is wrapped by a class key, which is protected by the device's hardware key and, for some classes, your passcode (Apple Platform Security: Data Protection). A vault does the same with your code:

  1. Your code is stretched into a wrapping key.
  2. The wrapping key unlocks a random vault key, stored only in encrypted form.
  3. The vault key unlocks the file keys that encrypt each photo, video and note.

Changing your code then only re-wraps the vault key, instead of re-encrypting every photo. A recovery phrase can be a second wrapping of the same vault key, so either the code or the phrase opens the vault. Noxium's layers are explained on our on-device encryption page.

How does an encrypted backup stay private?

By encrypting on the phone before anything is uploaded, so the cloud only ever stores scrambled data. This is end-to-end encryption.

The test is simple: could the company reset your code by email and give you your photos back? If yes, it can reach the key, and so could anyone who gets into its systems or your email. If no, only you can decrypt the backup, which is also why losing both your code and your recovery phrase means losing access. If that's happened, see forgot your photo vault password.

Noxium encrypts everything on the device, including names, dates and places, and only encrypted data goes to your own private iCloud (CloudKit). Nobody can reset your pattern: not us, not Apple.

Doesn't the iPhone already encrypt my photos?

Yes, with keys tied to your device and passcode. Once the iPhone is unlocked, anyone holding it can open Photos, so a vault adds a second lock with its own key.

  • On the iPhone. iOS encrypts each file with its own key under Data Protection, with key management rooted in the Secure Enclave (Apple Platform Security: Encryption overview). That protects a lost, locked phone. It doesn't separate one app's photos from someone who knows your passcode.
  • The Hidden album. It needs Face ID or your passcode to open, but it's the same passcode, and it syncs to your other devices. See how to lock photos on iPhone.
  • iCloud Photos. With standard data protection, Apple holds the keys. With Advanced Data Protection on, iCloud Photos is end-to-end encrypted (Apple: iCloud data security overview).

A vault that encrypts with a key from its own code means your iPhone passcode alone doesn't open it.

How can you tell if a vault app really encrypts?

Read what it names. There's no single best iPhone encryption app for everyone, but a trustworthy one tells you these things:

  • The cipher and the key derivation (for example AES-256-GCM and Argon2id), not just "secure".
  • That encryption happens on the device, before backup.
  • Whether it can reset your code by email. If it can, it can reach your key.
  • That its backup is encrypted with your key, not just "secure cloud".
  • Ideally, published encryption code or an independent review.

What can encryption not protect against?

  • Someone watching you enter your code, or making you enter it. A decoy vault helps with the second, not the first.
  • An open vault. While it's unlocked on screen, the photos are visible. Good apps hide content in the app switcher; Noxium also hides it during screen recording.
  • A short code. Slow key derivation helps, but a 4-digit PIN can still be tried exhaustively.
  • Copies outside the vault, such as originals left in Photos, Messages or Recently Deleted.

Questions people ask

How does a vault app work?

It stores your photos inside the app behind its own code. A good one also encrypts each photo with a key that only your code unlocks, so the stored files are unreadable without it.

What is the best encryption app for iPhone?

There's no single best one. Pick a vault that names its cipher (such as AES-256-GCM), encrypts on the device before backup, and can't reset your code by email. We compare apps in our vault app comparison.

Are photo vault apps encrypted?

Some are, some don't say. Of the 9 rival listings and help pages in our table, 2 name AES-256-GCM, 2 more name AES, and 2 don't mention encryption.

What is Argon2id?

A key derivation function that turns a password or pattern into a key, using a set amount of memory and time for each guess, so guessing codes is expensive. It's standardised in RFC 9106.

Can an encrypted vault be hacked?

The cipher itself isn't the weak point. Short codes, codes seen by someone else, and unencrypted copies left elsewhere are. Use a long code and remove originals after importing.
